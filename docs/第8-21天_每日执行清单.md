# 第 8–21 天｜真实使用验证（每日执行清单）

> 这 14 天的唯一目标：**回答「用户会不会真的每天打开用」**。
> 组织者的任务是**尽量少做事**——不引导、不教学、不改指标、不发版。所有需要的数据都由 App 自动写入 CSV。

## 1. 每天只做三件事（D1–D14）

| # | 动作 | 具体内容 |
|---|---|---|
| 1 | 发**一句**轻量提醒 | 用 `AI饮食管家_M4开跑包.md` §4 模板，一天一条，D14 换成导出提醒 |
| 2 | 异常**只记录、不干预** | 有人打不开/白屏 → 按开跑包 §7 处置并记入登记表备注；不要顺势教他别的用法 |
| 3 | 确认**没有发版** | 今天没部署、没改 `fridge-app/` 里的算法 / 打卡文案 / 首页布局 |

**明确不要做**：不发问卷、不打电话回访、不引导「今天试试周菜单」、不在群里表扬用得多的人、不改变打卡文案、不改 CSV 列、不改判定脚本。这些都会污染留存与采纳率。

## 2. 三项要记录的东西，其实都在 CSV 里

路线图要求「记录推荐是否被采纳 / 临期食材是否被成功消耗 / 用户放弃使用的原因」——这些**不需要额外表格**，App 已埋点，第 14 天导出即得：

| 路线图条目 | CSV 列 | 含义 |
|---|---|---|
| 每天轻量打卡 | `date`, `opened`, `cooked`, `cookCount` | 是否打开、今天照着做了吗、做了几顿 |
| 推荐是否被采纳 | `generatedCount`, `viewedRecipe`, `cooked` | 推荐展示数、点开菜谱详情、实际下厨 |
| 临期食材是否成功消耗 | `urgentSaved` | 累计临期救回数 |
| 放弃使用的原因 | `blocker` | 首页打卡「没做」时可顺手写一句卡点，自由文本 |
| 版本一致性 | `baseline` = `m4-1` | 不一致 → 数据不可比，按开跑包 §7 处理 |

判定时「推荐采纳率 = 全部『我做了』次数 ÷ 各用户累计推荐展示数之和（取每人最后一天快照）」，`m4-report.js` 已实现，**不要手工换算**。

## 3. 口径锁死（「不随意改变测试指标」）

以下五项在 D1–D14 期间**一个字都不改**，照 `AI饮食管家_M4开跑包.md` §6：

| 指标 | 目标 |
|---|---|
| D1 留存 | ≥ 40% |
| **D7 留存** | **≥ 25%** |
| **推荐采纳率** | **≥ 20%** |
| 激活率 | ≥ 70% |
| 人均每周临期消耗 | ≥ 2 样 |
| 护栏（忌口/过敏/误推自报卡点） | **0 容忍** |

`GO` 要求 D7 留存与采纳率**同时**达标；`INCOMPLETE`（不足 20 人 / 最长不足 14 天 / 可评估 D7 的用户不足 20）**不是「差一点就过」**，是结论暂不成立。**缺勤是真实数据，`opened=0` 要计入分母，不要删行、不要补 1。**

## 5. 异常处置速查（完整版见开跑包 §7）

| 现象 | 处置 |
|---|---|
| 403 / 白屏 | 重发完整链接、普通窗口重新打开；**记录断档天数，不要伪造补齐** |
| 样式没了 / 按钮没反应 | 关无痕、清站点数据后从完整链接重开；v1.6.2 有构建号自愈 |
| CSV 中间缺几天 | 真实数据，照收 |
| `baseline` 不是 `m4-1` | 数据不可比，冻结后重跑 14 天 |
| 有人反馈忌口/过敏误推 | **立即人工复核并暂停**，优先于任何增长指标 |
| 有人中途退出 | 记入登记表备注，用候补补位；样本不足就接受 `INCOMPLETE` |
