## 1. 在线 Demo 检查（真实网络请求，非推测）

站点靠 **Cookie 授权**：首次访问必须带完整 `?sharecode=...`，服务端下发 `__wb_rsc`（`HttpOnly / Secure / SameSite=None`），后续相对资源凭 Cookie 放行。

| 检查 | 结果 |
|---|---|
| 完整邀请链接 | **HTTP 200**，返回 `index.html` 21,889 bytes |
| 无 Cookie 直接访问根路径 / 任意资源 | **HTTP 403**（预期行为，不是故障） |
| 带 Cookie 后 11 个资源 | **全部 200**：`index.html` / `styles.css` / `data.js` / `engine.js` / `ai-adapter.js` / `app.js` / `manifest.json` / `sw.js` / `icon-192.png` / `icon-512.png`（含 icon-maskable） |
| Cookie 有效期 | 实测 `Expires` 对应 **2026-12-09 17:41**（约 30 天），大于 14 天验证期 |
| 资源内容一致性 | 各 JS/CSS 字节数与本地 v1.6.2 一致（21,889 / 30,119 / 22,266 / 38,369 / 11,821 / 92,287） |

**结论：可以分发。** 仍要在邀请话术里保留三条硬约束（完整复制链接、普通窗口、14 天不清 Cookie 不换设备），原因见 `AI饮食管家_M4开跑包.md` §1.2。

> 补充：因为 `start_url="."` 走不带参数的根路径、靠 Cookie 仍返回 200，「安装到主屏」可以照常建议参与者使用。

### 发现 1 处待迭代瑕疵（本轮**不修**）

**周菜单页的日期被挤成竖排**（见 `docs/mobile-week-issue.png`）：390 宽下「11 月 9 日」逐字换行，可读性差。

- 根因：`styles.css` 的 `.day-col{min-width:150px}` 与 640 断点里的 `.week-grid{grid-template-columns:repeat(7,minmax(132px,1fr))}` 冲突；`.day-head` 为 `flex + space-between`，`.day-date` 空间不足后换行。
- 建议修法（验证期结束后再动）：在 `@media (max-width:640px)` 内补 `.day-col{min-width:140px}`、`.day-date{white-space:nowrap}`、`.day-head{flex-wrap:wrap;gap:2px}`，并把 `minmax(132px,1fr)` 与列宽对齐。
- **为什么现在不改**：`AI饮食管家_M4开跑包.md` §0 规定 D1 起 14 天内不发布任何版本、不改布局；修 CSS 必须重新发布线上才能保持仓库与线上一致，会重置 `m4-1` 冻结起点。列为**第 22–25 天迭代候选**，由组织者在拿到 GO/NO-GO 后决定。

### 可优化但不阻断

- 部分小控件未达 44×44 触摸目标建议：390 宽下 `plan` 40 个、`fridge` 27 个、`week` 21 个、弹窗 41 个，主要是分类 chip、每行删除图标、星级/标签按钮。它们没有造成误触或溢出，但小屏手指操作偏局促，同样列入**验证期后**的迭代候选。
- 顶部 9 个导航项在手机上是**横向滚动**的（首屏只露出前 5 个）。这是既有设计、可正常滑动，但陌生人可能不知道，已在 README 的 30 秒上手里补一句提示。

## 3. 复跑方式

```bash
# 手机端检查 + 重新抓演示截图（在本机仓库根目录）
node tools/capture-demo.js --app=./fridge-app --out=./.check-output

# 重新合成 30 秒 GIF 与社交预览图（需 pip install Pillow）
python tools/make-demo-gif.py --shots=./.check-output/screens --out=./docs
```

脚本会启动本地静态服务与独立 Chrome profile，结束后自动清理临时数据；不会写入 `fridge-app/`，也不会访问线上站点。
